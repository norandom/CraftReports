# Fixed GridCraft production profile — Design amendment proposal

Status: **proposal for independent Design review; no implementation GO**. Date: 2026-10-16. This adds a bounded decision to the accepted GridCraft Design and task 4 plan; it does not edit `design.md`, `tasks.md`, `spec.json`, report-model contracts, source, tests, budgets or release gates. The owner-authorized overnight workflow still requires an independent review and root integration decision before task 4. The current accepted real-browser baseline is GridCraft task 3, commit `a2c7782`, run `9b3b0dad-41f2-4e59-894a-9c0ebc45bd22`, reviewed in `artifacts/gridcraft/task-3/final-review.md`.

## Boundary and reason for the amendment

GridCraft owns target-specific admission, workbook mapping, observed UI and saved-byte fidelity. Report-model owns target-neutral preparation, semantic values, the closed capability/property vocabulary and the optional supplied-descriptor behavior. Snapshot-runtime owns run pins; the kernel owns guards/results. This amendment changes only the GridCraft first profile and its handoff. Pure `themes.values` and `themes.resolve` remain unchanged. No general target-capability interpreter, alternative browser bridge, package owner, dependency or numeric cap is added.

The accepted `theme-support-amendment.md` requires a supplied `CapabilityStatus` set to support every requested property: 22 names unconditionally and `format.decimal_places` / `format.date_pattern` when declared. Its three capabilities must share mode/release/profile pins. Task 3 proves selected literal text, small positive integers, a chart null gap, one bold/fill style, the retained `0.00;-0.00` number-format string, one visible blue series, and outside cell/textbox preservation. Those eight mixed observations cannot truthfully be published as 24 supported theme properties. Marking untested entries `supported` to make `resolve_theme` succeed is prohibited.

Use the already accepted no-target path for this first GridCraft workflow: the trusted report preparer calls `resolve_theme(theme, overrides, support=None)` and retains the complete `ResolvedTheme` and `required_capabilities` in the pinned `PreparedReport`. This leaves target fit unevaluated. A caller-supplied support descriptor continues to use the existing strict report-model check; this amendment gives it no exception and does not treat a rejected supplied descriptor as supported. Whether the prepared result came from a target-neutral or supplied-descriptor request, GridCraft applies its own trusted bind check. Neither a caller's descriptor nor a preparation receipt is GridCraft observation evidence. The app check must run before bootstrap or any later UI edit. If review concludes that a target-supplied descriptor is mandatory for this path, stop and obtain a separate independently reviewed report-model contract amendment; task 4 must not bypass or weaken the current resolver.

The first profile is one immutable app-owned declaration for the official GridCraft web 0.7.0 archive SHA-256 `ad10af2baf9c7ed4ccbd81e32b37698f5075cdf4f26b726fee7fc7938a3a8d27`, loaded JS `cd4d0aa76dfb703870a6b5dbf63c88217221ebb7aac5c491f51c0e1b2d8fcbd9`, loaded WASM `d1f2cfa583aea14443f0f68ee55403c18296cae237d1cfa7a2fdc3d886d4eb74`, browser mode and the measured headless Chromium 156.0.8078.4 / 1600×1100 SwiftShader profile. Give it an exact `VersionPin(identity, version, content_digest)` from its canonical closed declaration. That pin, release/build hashes, browser/deployment/context/page/document/navigation identity and marker travel through `BrowserTarget`, `OwnedLayout`, `MappingPlan`, observations and retained app evidence. The app's support disclosure is a closed, release/profile-bound **conditional operation profile**, not a blanket `report.semantic_style` assertion. Its property matrix can use the existing 24 names and `supported | untested | unsupported` statuses for discovery, but unknown/untested properties remain such even if a particular admitted report does not use them. In particular, do not pass that partial matrix to the existing target-aware `resolve_theme` and call its expected rejection a preparation defect. GridCraft's bind checker maps the fixed candidate's actually rendered fields to actual addresses/chart attributes; it does not reinterpret arbitrary report-model theme declarations. Every applied field, including a library/default font, size, alignment, wrap, line/grid choice and width/height, needs positive matching evidence before the operation profile becomes supported. Unused semantic-role styles may remain declared in `ResolvedTheme` but are frozen by the full candidate equality check; the profile does not claim they render or support arbitrary content later.

## Property-level proof and status decision

The candidate theme and fixture must be frozen **before** the additional profile run. The table below names every property in the accepted vocabulary. “Task 3” is reusable only for the exact exercised release/build/profile, cell/chart value and assertion; the focused new run establishes the final candidate and any new values. It must retain actual app-saved files, independent inspection, selected-cell/UI observations, fresh-context reopen, screenshots/video/diagnostics and cleanup evidence. A property without its stated proof remains untested and makes an applicable bind unavailable.

| Properties | Existing basis | Additional proof or first-profile disposition |
| --- | --- | --- |
| `text.bold`, `text.fill` | Task 3 saved/reopened A1 bold and `#DCE6F1` fill. | Reuse only if the final candidate uses that exact cell/style; inspect every other rendered role/cell that claims these values. A role/cell variation needs a new assertion. |
| `text.font_family`, `text.size_pt`, `text.italic`, `text.color`, `text.alignment`, `text.wrap` | No accepted field-by-field fidelity assertion. | Inspect actual initial/save/reopen cell styles for every rendered role and compare to independently fixed expected font, size, italic, color, alignment and wrap values; include one admitted boundary-length label and visible fit/wrap observation. Defaults are checked, never assumed. |
| `format.kind`, `format.decimal_places`, `format.negative_style` | Task 3 proves text and small-int cell types and retains one `0.00;-0.00` format string, not general kinds or negative rendering. | Check exact text/int64 schema-to-cell types and the selected two-decimal display plus saved format after updates/reopen. Show `0`, `1`, `9999` and an interior integer remain exact. Reject negative inputs; do not claim negative rendering merely because the format contains a negative section. |
| `format.date_pattern` | No date/datetime in admitted data. | Untested and inapplicable to this fixed candidate. Any date/datetime/declared date pattern rejects. Do not publish it as supported. |
| `grid.show_gridlines`, `grid.header_height`, `grid.column_width` | No accepted grid-property checks. | Assert exact worksheet view/dimension properties in initial, actual saved and reopened files and visible geometry in the selected browser profile. If the released app changes them, this profile remains unavailable or the candidate must be narrowed and reviewed. |
| `chart.series_colors` | Task 3 visible blue line for one color. | Compare actual chart XML color to exact candidate hex and inspect rendered color after both changes and fresh reopen. |
| `chart.line_width`, `chart.legend`, `chart.grid` | No accepted field-level assertions. | Compare actual chart XML and visible chart for exact candidate line width, legend and grid settings before/after Save and reopen. No implied support from XlsxWriter input. |
| `chart.null_gaps` | Task 3 gap XML and visible no-bridge assertion. | Reuse for identical gap placement/route; verify the final candidate's second-category gap and real rendered chart after update/reopen. |
| `table.typed_null`, `table.null_marker` | Task 3 blank B7 round-trips as `None`; no simultaneous visible marker proof. | Table values are nonnullable in this profile; both properties remain untested for table-null presentation and requests with table null reject. Chart null is governed separately by `chart.null_gaps`. |
| `table.empty_headers`, `table.empty_note` | No empty report exercise. | Four rows are required; both remain untested for empty behavior and an empty request rejects. |

The focused proof also exercises `=1+1` and URL-looking text as literal strings; boundary-length and non-ASCII UTF-8 text either pass actual UI/save/reopen comparison or the text bound is narrowed to the proved range. It verifies one-time bootstrap, two same-document updates, fixed chart categories/references, original and verifier-context marker, outside `M1`/textbox signatures, pre-mutation conflict, source type/value and no interpolation. Reuse task 3's actual-save/reopen/conflict evidence where inputs and expectations are identical; add assertions only for the changed candidate fields and boundary cases. If any selected property fails, the profile stays untested/unavailable. Do not compensate by declaring the failed property unused when the candidate still applies it.
