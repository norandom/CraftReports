## Cross-task integration and boundary audit

- Composition supplies the same application-owned `Execution` facade and `TransportWire` port to both interfaces. Concrete codecs remain adapters; interfaces do not import adapters. Activation publishes immutable registry/manifests only after settings, graph, lifecycle and binding checks.
- Coarse access precedes private input preparation; resource checks precede required-service/capability checks. Mandatory guarantees are added independently of plugin-requested declarations. Command admission owns normalized retry identity, retained lookup, atomic admission and authoritative guard authority. Existing retry lookup precedes a new version check.
- Application execution owns admitted work beyond the response waiter, capacity and shutdown. It reads back journal/result/evidence state before declaring completion. Receipt/result authorization occurs before protected content lookup. Query/result inspection does not mutate the synthetic canonical target.
- Host assembly retains the validated listener, explicitly supplied providers and activation resources. MCP session lifespan and bounded execution shutdown precede provider closure; failed cleanup remains failed. Tests own their loopback subprocesses, ports, tokens and evidence folders.
- Production providers, persistence/ORM, report/packs, GridCraft packages and browser/XLSX acceptance were not absorbed into the kernel. The historic GridCraft prototype and separate rendering-only Compose probe are not kernel acceptance evidence. Changes to core identity, retry normalization, receipt/evidence semantics or provider guarantees require affected downstream consumer revalidation.

The Design file plan permits responsibility-based splits. Actual implementation adds cohesive value/transport/admission modules within the same owners. Fixture helpers are mostly under `tests/kernel` with `tests/fixtures` and an independently installable synthetic fixture package; none is a production provider fallback. The planned single `docs/kernel-contract.md` is represented by capability-authoring, kernel-host, rest-client, mcp-client and result-readback documents. These are organization variations, not new capability ownership or changed public semantics. The approved result-readback amendment is implemented on both public interfaces.
