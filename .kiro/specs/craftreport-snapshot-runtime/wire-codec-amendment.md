## Producer request and runtime handoff

`publication_codec(limits).decode(payload) -> JsonObject` returns a recursively immutable, validated, normalized producer object. Its closed schema contains version, feed/version, ordered datasets/metrics and producer observation/generation times. It rejects service timestamps, digest, retry identity, operation identity and all other unknown properties. The request remains producer content, rather than pretending to be an accepted `Snapshot`.

The codec uses the existing inward field/dataset/metric validation and shared scalar decoder to validate exact meaning. Normalization produces canonical decimal strings at declared scale, canonical positive producer-version strings and fixed UTC timestamp strings. No persisted or accepted state is created. The same explicit conversion functions serve request validation and later finalized snapshot construction; there is no parallel handwritten field/type validator.

Expose the adapter implementation `finalize_snapshot(content: JsonObject, received_at: datetime, accepted_at: datetime) -> tuple[Snapshot, bytes]` as the typed runtime handoff. It conforms to the inward `data.ports.SnapshotFinalizer` callable. Its documented precondition is the normalized immutable output of this codec. Task 4.1 supplies actual service times. The function builds the existing `Snapshot` using the shared conversion path and the canonical producer digest; it returns that finalized snapshot plus the exact canonical producer bytes whose SHA-256 equals `snapshot.content_digest`. It does not fabricate times or introduce another producer value type. It does not rerun Pydantic schema validation or introduce a second normalizer. Construction retains the authoritative inward dataclasses' invariant checks.

At tasks 4.1/4.2, `composition/snapshot_host.py` imports the concrete adapter finalizer and injects it as a `SnapshotFinalizer` into the runtime publication service. Runtime imports only the inward callable type and never imports an adapter or obtains a new import exemption. Runtime retains and reuses the returned producer bytes and `snapshot.content_digest` together with the finalized snapshot through its atomic storage effect. This is ordinary constructor/callable injection, with no new framework.

There are deliberately two lifecycle evaluations rather than a claimed single canonicalization pass: admission validates and normalizes the producer payload, serializes a bounded candidate full-read object using maximum service-field lengths and rejects an excessive result; finalization later serializes canonical producer content again from that immutable normalized payload, computes its digest and returns the bytes/digest with the snapshot. Those bytes and digest are then reused for persistence, rather than recalculated independently by runtime or storage. Task 4.1 additionally serializes the actual full-read object with the real service fields before commit. All evaluations use the same shared serializer/canonical profile. This small repeated serialization is explicit and preferable to a duplicate producer representation or an implicit cache carrying mutable admission state.

The snapshot result codec handles actual finalized `Snapshot` values through the same conversion/scalar functions. Its serialized object includes all closed producer and service fields and the exact digest. Provider verification of retained bytes/digest and real service timestamps remains owned by storage/publication tasks. Reader authorization, missing/conflict/unavailable behavior and durable effects remain outside this codec task.

## Shared scalar and canonical identity contract

Keep `encode_scalar(value: Scalar) -> JsonValue` and `decode_scalar(value: JsonValue, field: Field) -> Scalar` unchanged from the reviewed consumer seam. Int64 and producer versions use canonical decimal strings, while bool and null remain JSON literals. Text remains literal. Date and datetime parsing is schema-driven; datetime lexemes with more than six fractional digits are rejected before parsing and accepted timestamps normalize to UTC.

For a declared decimal field, validate the Decimal exactly against existing precision/scale rules, normalize losslessly to that scale with sufficient local decimal precision, normalize signed zero, and then call the shared `encode_scalar` on that normalized Decimal. The field-aware composition supplies scale without adding a field argument to `encode_scalar` or duplicating scalar serialization in report codecs. No float conversion or rounding is permitted. Generic parameter scalars use the reviewed explicit `kind`/`value` envelope; decoding does not infer scalar kind from a string's contents.

Producer canonical bytes use the existing canonical JSON facility: sorted object keys, compact UTF-8, original array order and its existing rejection of unsafe wide JSON numbers. Producer schema, feed/version, schema/data/metrics/provenance and producer timing participate. Service received/accepted times, retry and operation identities do not. SHA-256 hashes these bytes. Independent fixtures test lexical Decimal equivalence, service-time independence and producer-content/order differences.

## Limits and admission evidence

Defaults remain 1,048,576 input/output bytes, depth 32, 16 datasets, 128 fields per dataset, 10,000 total rows, 100,000 total cells, 128 metrics, 10,000 total metric points and 4,096 code points per string. Configuration can only lower these defaults. Before admission, the request codec calculates the complete canonical `snapshot.read` object bound including the 64-character digest and both maximum-length closed UTC service timestamp strings. It checks metadata, separators, escaping and producer timing as part of the same actual serialization. It rejects an exceeded output bound as a named limit before any command identity exists. No fake service time is exposed as an inward or returned snapshot.

The exact final serialization check with actual accepted service times remains mandatory in task 4.1 before the transaction commits, plus defensive readback checks. This amendment does not claim those future effects.
