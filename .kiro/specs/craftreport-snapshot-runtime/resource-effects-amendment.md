## Schema version 3

Keep deployment, commands and observations definitions unchanged. Introduce only:

- feeds: feed_id String primary key; subject String nonnull; high_water Integer nonnull positive; revision Integer nonnull positive. Database deployment identity supplies scope. Ownership is retained once, not a caller-supplied scope.
- snapshots: feed_id String plus producer_version Integer composite primary key; feed_id foreign key to feeds.feed_id; producer_version positive; operation_id String nonnull foreign key to commands.operation_id and unique; content_digest String nonnull; producer_bytes LargeBinary nonnull; snapshot_bytes LargeBinary nonnull; snapshot_digest String nonnull. Canonical producer bytes establish content identity; exact canonical snapshot bytes include distinct producer and service times and establish precise readback. Avoid redundant timestamp columns; independently compare decoded snapshot identities/digest/times with producer bytes and the relational key on read.
- evidence: identity String primary key; operation_id String nonnull foreign key to commands.operation_id; reference_bytes LargeBinary nonnull; reference_digest String nonnull; fact_bytes LargeBinary nonnull; fact_digest String nonnull. Exact reference contains scope, operation/key and full declared resource versions. Trusted ownership derives through retained command, rather than redundant editable owner fields. This same table supports task 3.3 preparation facts without another evidence authority.

## Lease, version and atomic effect behavior

One process-local guard instance owns deterministic (kind, identity) sorted per-resource asyncio locks. Deduplicate/reject repeated resource preconditions with existing contract validation. Acquire each lock within a bounded timeout, releasing every acquired lock in finally for conflict, timeout or cancellation; no SQL transaction spans a lock wait or await. Under acquired locks, one short transaction reads authoritative feed revisions or snapshot content digests; absent supported resources have token absent, but ResourceReader reports Missing for absent content. Unsupported kinds fail unavailable rather than invent absence. Snapshot identity parses its final colon-delimited canonical positive version and verifies the full retained identity.

Lease.assert_current verifies active lifetime, owning task not cancelling, and exact authoritative versions through storage. Exiting acquire permanently invalidates the lease. Apply rejects foreign/fabricated/inactive/unrelated leases, calls assert_current immediately before effect, then rechecks lease activity and authoritative preconditions inside the short effect transaction. This closes cancellation/change races between the asynchronous check and worker execution. An executing transaction can commit before cancellation arrives; the committed operation-linked fact then remains discoverable and must not be blindly replayed. Tests distinguish cancellation before mutation from lost postcommit acknowledgement.

Atomic transaction order: validate command/lease and decoded snapshot; compare same-version content first; identical returns existing identity with EffectDisposition.NONE and no invented new evidence; changed content returns VersionConflict; unseen lower version returns VersionConflict and leaves high-water unchanged. For a new higher version, insert/update the owned feed with revision CAS, insert immutable snapshot and persist evidence/fact in the same transaction. The existing protocol has no stale-specific variant, so the later publication handler maps version comparisons to its business result statuses without altering provider contracts. Duplicate operation_id cannot create another snapshot. Failed CAS or constraint errors roll back all three effects.

Return ResourceEffect(APPLIED, full declared post-effect resource versions, evidence). The evidence scope is snapshot_persisted; its fact is a closed JSON object carrying feed_id, producer_version string, content_digest and original operation_id. EvidenceRef.content_digest hashes canonical fact bytes, not its own serialized reference. Generate opaque identity once. All declared resource pins come from authoritative postcommit content (publication declares just the feed); the newly created snapshot identity is in the fact rather than adding an undeclared pin. Readback independently verifies snapshot/fact/reference bytes and digests before exposing them. Task 3.3 supplies the full EvidenceReader availability policy and protected read API; task 3.2 tests inspect committed bytes directly.
